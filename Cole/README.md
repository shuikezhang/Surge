# Cole Surge 配置（Sub-Store 文件生成）

本目录包括 `cole-surge-template.conf`、`cole-substore.js`、本 README。前两者仅为无凭据模板与生成代码，不含节点、订阅地址或密码；模板含占位符，不能直接导入 Surge。配置是独立完整主配置，并非 Surge 模块，不会保留旧配置的其他设置。使用前备份旧配置。

## 创建 Sub-Store 文件

1. 使用支持 Node.js 的 Sub-Store 后端，预先准备名为 `Surge组合` 的集合；保留自己的来源及容错设置。若名称不同，在脚本中修改 `SUB_NAME`；无需填写任何订阅 URL 或凭据。
2. 在 Sub-Store 新建文件，将 `cole-surge-template.conf` 的原文作为文件内容或远程文件来源，再添加文件的「脚本操作」，代码为 `cole-substore.js`（可粘贴代码，或按界面支持的方式引用脚本 URL）。这是文件处理脚本，不是普通节点订阅的节点操作脚本。脚本引用 `node:crypto`，不保证移动端等非 Node 环境运行。
3. 用 Sub-Store 该文件的分享/下载链接在 Surge 新建或更新配置，不要把 GitHub 的原始模板 URL 当成生成后的配置。链接由自己的 Sub-Store 界面生成，分享链接及生成文件都包含或可取得私人节点凭据，必须保密；仅经可靠的访问控制与安全通道使用，勿公开到 GitHub。不要上传导出结果或输出节点日志。
4. 导入前核对输出不是错误信息、包含非空 `[Proxy]`，且不存在 `@@COLE_`；在 Surge 解析和连接测试后，再根据实际网络选择 PROXY、AIGC、Telegram 和各地区策略，查看请求日志核实分流。Sub-Store 出错或无节点时不应将旧缓存当作新配置；客户端更新失败时的旧配置保留行为取决于客户端。

## 部分节点与失败行为

沿用集合及子订阅现有的远程源失败容错，不强制将忽略失败关闭；因此某些源失败时可能只导出部分节点，数量可能随时间变化，HTTP 200 不表示各源完整。上游解析/处理器也可能在脚本之前过滤节点。显式跳过 VLESS，名称匹配流量、订阅等提示词的项目也过滤；真实格式化器不能导出的其他类型、空结果、模板标记异常等会令脚本抛错。无可用代理时不生成空节点配置，也不主动回退 DIRECT；失败不等同于客户端必然断网，真实客户端和缓存行为仍须验收。

按名称关键词分 HK、SG、JP、US、TW、KR、DE、OTHER。匹配不到的进入 OTHER；名称可能误判，也可能多地区匹配。空地区组使用 `select, REJECT`，不会因地区无节点自动直连，但可能导致流量被拒绝。默认 PROXY 首选 HK AUTO，AIGC 首选 US AUTO，Telegram 首选 SG AUTO；这些地区即使为空也不会自动切换到其他地区，须手动选择有节点的组（AIGC/Telegram 没有 OTHER，必要时在模板/脚本中修改或自行安排）。GLOBAL 包含所有组及节点，但不是规则默认目标。节点优先显示清理后的可读原名；当同名（忽略大小写）或与固定策略组、内置策略名冲突时，才添加 ` · ` 和代理参数 SHA-256 的前 6 位十六进制短后缀。先保留无冲突原名，并检测后缀与其他名称的二次碰撞，必要时逐步延长至 24 位；仍无法消解则构建失败。逗号等配置分隔符替换为全角，控制及双向控制字符清理，原名限 120 个 Unicode 码点。相同代理参数仍去重并合并匹配地区；如有多个原名，按 Unicode 字符顺序选最小清理后名称。后缀不代表匿名化。**首次切换、别名增删、节点参数变化，或之后同名/冲突节点的出现或消失，都可能改变名称并影响 Surge 已保存的节点选择**；导入后请重新检查选择。

规则保持源顺序：指定直连例外、AI、Telegram、China、Global、GEOIP CN、FINAL PROXY。直连例外为有意行为；其中 `DOMAIN-KEYWORD,oa,DIRECT` 匹配范围宽，可能导致非预期直连，使用前务必审阅是否删除。Windows 进程名规则在非 Windows 设备上未必匹配。远程 MagicRule 列表是固定 URL 快照，可能不可达、下架或有版本兼容差异；与原 Clash 行为不能保证完全等价。AnyTLS 等类型是否可实际连接取决于 Surge 客户端版本与具体参数。

本候选基于 Sub-Store 2.44.2 引擎及私密真实集合样本做脱敏验证；未在真实 Surge 设备解析、测速或通流，也未将本候选配置写入生产 Sub-Store 文件 API 测试。请先自行检查可用节点、空组及流量路径，正式使用后仍需监控。
